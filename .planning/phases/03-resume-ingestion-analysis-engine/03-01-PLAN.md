# Phase 03: Plan 01 — Document Ingestion, Magic Byte Verification & Safe Text Extraction

**Implement defensive file ingestion, magic byte verification (`%PDF-`, `PK\x03\x04`), isolated file storage (`storage/resumes/<uuid>.<ext>`), SQLAlchemy 2.0 Resume ORM model with Alembic migration, and safe text extraction via `pdfplumber` / `python-docx`.**

---

## Tasks

### Task 1: Dependencies & Storage Configuration
- Add `python-multipart>=0.0.9`, `pdfplumber>=0.11.0`, `python-docx>=1.1.0`, and `google-genai>=0.1.0` to `backend/requirements.txt`.
- Update `backend/app/core/config.py` with:
  - `RESUME_STORAGE_DIR: str = "storage/resumes"`
  - `MAX_RESUME_SIZE_BYTES: int = 5 * 1024 * 1024` (5 MB)
  - `GEMINI_MODEL: str = "gemini-2.5-flash"`
- Create `backend/storage/resumes/` directory with `.gitkeep`.

### Task 2: Resume ORM Model & Alembic Migration
- Create `backend/app/models/resume.py` (`Resume` model matching `docs/BACKEND_SCHEMA.md` §2.5):
  - `id`: `String(36)` Primary Key (UUIDv4)
  - `user_id`: `String(36)` Unique Foreign Key to `users.id` with `ON DELETE CASCADE`
  - `file_name`: `String(255)`
  - `file_path`: `String(500)`
  - `file_size_bytes`: `Integer`
  - `mime_type`: `String(100)`
  - `raw_text`: `Text`
  - `parsed_data`: `JSON` (or JSONB)
  - Timestamps `created_at`, `updated_at` via `CommonModelMixin`
- Register `Resume` in `backend/app/db/base.py`.
- Create Alembic migration `backend/alembic/versions/002_create_resume_table.py`.

### Task 3: Document Extractor & Sanitization Service
- Create `backend/app/services/document_extractor.py`:
  - `verify_file_magic_bytes(content: bytes, filename: str) -> str`: Verifies `%PDF-` for PDF, and `PK\x03\x04` zip header verifying `[Content_Types].xml` or `word/document.xml` for DOCX. Raises `ValidationError` if extension is spoofed or binary signature is invalid.
  - `extract_text_from_pdf(content: bytes) -> str`: Uses `pdfplumber` to extract plain text across all pages.
  - `extract_text_from_docx(content: bytes) -> str`: Uses `python-docx` to extract text paragraphs and tables.
  - `extract_and_sanitize_text(content: bytes, filename: str) -> str`:
    - Dispatches to PDF/DOCX extractor via `asyncio.to_thread`.
    - Checks extracted text length >= 50 non-whitespace characters (rejects empty/scanned PDFs with HTTP 422 `ValidationError: "No extractable text found. Please upload a standard text-based PDF/DOCX resume."`).
    - Strips null bytes (`\x00`) and control characters.
    - Truncates text to max 30,000 characters.

### Task 4: Unit & Extraction Tests
- Create `backend/tests/test_resume_upload.py`:
  - Valid PDF magic bytes accepted.
  - Valid DOCX magic bytes accepted.
  - Spoofed files (e.g. `.exe` renamed to `.pdf`) rejected with HTTP 422.
  - Files > 5 MB rejected with HTTP 422.
- Create `backend/tests/test_resume_extractor.py`:
  - PDF text extraction with multi-page structure.
  - DOCX text extraction.
  - Scanned / empty PDF (< 50 chars) rejection with HTTP 422.
  - Text length bounding at 30,000 characters.
