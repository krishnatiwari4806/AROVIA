# Phase 06: Plan 02 — Evaluation Orchestrator, Persistence & REST Endpoints

**Implement the `EvaluationService` orchestrator, focus-adaptive composite score calculator, atomic database persistence, and evaluation REST endpoints.**

---

## Tasks

### Task 1: EvaluationService Orchestrator & Scoring Formulas
- Create `backend/app/services/evaluation_service.py`:
  - `compute_turn_composite_score(scores: dict, interview_focus: str) -> int`:
    - Technical Core & System Design: `0.35 * correctness + 0.25 * relevance + 0.20 * keywords + 0.10 * clarity + 0.10 * confidence`
    - Behavioral: `0.30 * relevance + 0.30 * clarity + 0.20 * confidence + 0.10 * correctness + 0.10 * keywords`
  - `evaluate_session(db: AsyncSession, current_user: User, session_id: str) -> SessionEvaluationReportResponse`:
    - Validates session ownership and verifies session has completed turns (`status in ['evaluating', 'completed']`).
    - If already evaluated (`session.status == 'completed'` and `session.overall_score is not None`), returns existing saved evaluation report.
    - Fetches all answered turns for the session.
    - For each turn: runs local filler-word heuristic analysis (`analyze_speech_confidence`).
    - Invokes `gemini_service.evaluate_interview_session` with full session context.
    - Blends local heuristic confidence (40%) + AI confidence (60%) for each turn.
    - Computes composite `turn_score` for each turn using focus-adaptive weights.
    - Updates each `InterviewQuestionTurn` row with dimensional scores, turn score, and `evaluation_data`.
    - Computes session dimension averages (relevance, correctness, keywords, clarity, confidence).
    - Computes session `overall_score` (0–100).
    - Updates `InterviewSession` with `overall_score`, `dimension_scores`, `evaluation_report`, `status = 'completed'`, and `completed_at = now()`.
    - Commits transaction and returns `SessionEvaluationReportResponse`.
  - `get_session_evaluation(db: AsyncSession, current_user: User, session_id: str) -> SessionEvaluationReportResponse`:
    - Retrieves saved evaluation scorecard from database or triggers evaluation if not yet completed.

### Task 2: REST API Endpoints
- Update `backend/app/api/v1/endpoints/interviews.py`:
  - `POST /sessions/{session_id}/evaluate` -> `SessionEvaluationReportResponse` (Status 200)
    - Triggers the complete evaluation pipeline and finalizes the session.
  - `GET /sessions/{session_id}/evaluation` -> `SessionEvaluationReportResponse` (Status 200)
    - Retrieves the completed session scorecard, radar metrics, strengths, improvements, and turn breakdowns.

### Task 3: Integration Tests for Evaluation Pipeline & Endpoints
- Create `backend/tests/test_evaluation_endpoints.py`:
  - Test `POST /sessions/{id}/evaluate` executes full evaluation pipeline and updates session status to `completed`.
  - Test `GET /sessions/{id}/evaluation` returns saved dimensional scorecard, radar averages, strengths, and improvements.
  - Test focus-adaptive score weighting difference (Technical vs Behavioral sessions).
  - Test unauthorized user cannot access another candidate's evaluation report (HTTP 404/403).
  - Test idempotency: evaluating already completed session returns cached report without duplicate processing.
