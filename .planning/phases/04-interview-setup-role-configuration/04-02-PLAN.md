# Phase 04: Plan 02 — Job Description AI Parsing, Session Management Service & REST Endpoints

**Implement Gemini structured Job Description extraction (`google-genai` SDK), single active session enforcement, session creation/abandonment lifecycle in `InterviewService`, and REST endpoints (`/presets`, `/sessions`, `/sessions/active`, `/sessions/{id}`, `/sessions/{id}/abandon`).**

---

## Tasks

### Task 1: Job Description AI Extraction in GeminiService
- Update `backend/app/services/gemini_service.py`:
  - Define `ParsedJobDescription` schema:
    - `job_title: Optional[str]`
    - `required_skills: list[str]`
    - `core_responsibilities: list[str]`
    - `key_technologies: list[str]`
    - `experience_summary: str`
  - Add method `async def parse_job_description(self, raw_text: str) -> ParsedJobDescription`:
    - Wraps text in `<job_description>` tags.
    - Uses `google-genai` SDK with `response_schema=ParsedJobDescription` and `response_mime_type="application/json"`.
    - 1 retry on transient network errors.
    - Graceful fallback to empty/heuristic schema if AI service is temporarily unavailable during setup (so JD upload doesn't block interview creation).

### Task 2: Interview Session Service Implementation
- Create `backend/app/services/interview_service.py`:
  - `InterviewService`:
    - `create_session(db: AsyncSession, current_user: User, request: InterviewSessionCreateRequest) -> InterviewSession`:
      1. Check for existing active session (`user_id == current_user.id` and `status == 'in_progress'`). If found, raise `ConflictError("An active interview session is already in progress.", error_code="ACTIVE_SESSION_EXISTS", details={"active_session_id": existing.id})`.
      2. Sanitize `custom_job_desc` if provided (strip null bytes and control characters).
      3. Parse JD via `gemini_service.parse_job_description` if provided.
      4. Derive `planned_core_questions` (6 for `full`, 3 for `quick`) and `max_total_turns` (9 for `full`, 5 for `quick`).
      5. Fetch candidate's active `Resume` record (if any) to populate `resume_id`.
      6. Create and persist `InterviewSession` row.
    - `get_active_session(db: AsyncSession, current_user: User) -> InterviewSession`:
      - Returns active `in_progress` session or raises `NotFoundError("No active interview session found.", error_code="NO_ACTIVE_SESSION")`.
    - `get_session(db: AsyncSession, current_user: User, session_id: str) -> InterviewSession`:
      - Fetches session by ID ensuring `user_id == current_user.id`.
    - `abandon_session(db: AsyncSession, current_user: User, session_id: str) -> InterviewSession`:
      - Marks session `status = 'abandoned'` and `completed_at = now()`.

### Task 3: REST API Endpoints & Router Mounting
- Create `backend/app/api/v1/endpoints/interviews.py`:
  - `GET /presets` -> `PresetsCatalogResponse`
  - `POST /sessions` -> `InterviewSessionResponse` (Status 201)
  - `GET /sessions/active` -> `InterviewSessionResponse` (Status 200)
  - `GET /sessions/{session_id}` -> `InterviewSessionResponse` (Status 200)
  - `POST /sessions/{session_id}/abandon` -> `InterviewSessionResponse` (Status 200)
- Mount `interviews.router` in `backend/app/api/v1/router.py` with prefix `/interviews`.

### Task 4: Integration Tests
- Create `backend/tests/test_interview_jd_parser.py`:
  - Test JD sanitization (control characters stripped, 10k character limit).
  - Test `parse_job_description` with mock Gemini response.
  - Test fallback parsing when Gemini is unreachable.
- Create `backend/tests/test_interview_sessions.py`:
  - `POST /sessions` creates standard session (6 core, 9 turns) with `in_progress` status.
  - `POST /sessions` creates quick practice session (3 core, 5 turns).
  - Test single active session conflict: attempting second session returns 409 `ACTIVE_SESSION_EXISTS`.
  - `GET /sessions/active` returns active session metadata.
  - `POST /sessions/{id}/abandon` abandons session, allowing a new session to be created.
  - `resume_id` linking: session links candidate's active resume.
  - `ON DELETE SET NULL` verification: deleting resume sets `session.resume_id = NULL` without deleting the session.
