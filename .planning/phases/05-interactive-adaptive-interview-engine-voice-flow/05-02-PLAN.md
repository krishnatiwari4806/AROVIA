# Phase 05: Plan 02 — Backend Turn Transition Service & REST Endpoints

**Implement the interview turn progression engine in `InterviewService`, turn endpoints (`/start`, `/current-turn`, `/turns/{id}/answer`, `/turns`), turn duration tracking, and session completion transitions.**

---

## Tasks

### Task 1: InterviewService Turn Progression Engine
- Update `backend/app/services/interview_service.py`:
  - `start_interview(db: AsyncSession, current_user: User, session_id: str) -> InterviewQuestionTurn`:
    - Validates session ownership and `status == 'in_progress'`.
    - If turns already exist, returns existing turn 0.
    - Otherwise, loads candidate resume & JD context, calls `gemini_service.generate_initial_question`, creates `InterviewQuestionTurn` (turn_index=0, type="core"), updates `session.current_turn_index=0`, and commits.
  - `get_current_turn(db: AsyncSession, current_user: User, session_id: str) -> InterviewQuestionTurn`:
    - Returns latest turn for the session or raises `NotFoundError`.
  - `submit_turn_answer(db: AsyncSession, current_user: User, session_id: str, turn_id: str, request: TurnAnswerSubmissionRequest) -> TurnAnswerSubmissionResponse`:
    - Validates session and turn existence, checks turn belongs to session.
    - Prevents duplicate answer submission if turn already has `candidate_answer`.
    - Updates turn with `candidate_answer` and `turn_duration_sec`.
    - Counts completed core turns and follow-up turns in session.
    - Calculates remaining core questions and remaining follow-up budget based on `session.practice_mode` (Full: 6 core/3 follow-ups; Quick: 3 core/2 follow-ups).
    - Checks if interview should terminate (e.g. all core questions completed and no follow-up, or total turns == `max_total_turns`).
    - If concluding:
      - Marks session `status = "evaluating"`, `completed_at = now()`.
      - Returns `is_interview_complete=True`, `next_turn=None`.
    - If continuing:
      - Invokes `gemini_service.evaluate_and_generate_next_turn` with transcript context.
      - If decision is follow-up: creates turn with `is_follow_up=True`, `parent_turn_id=current_turn.id`, `question_type="follow_up"`.
      - If decision is next core: creates turn with `is_follow_up=False`, `parent_turn_id=None`, `question_type="core"`.
      - Updates `session.current_turn_index += 1`.
      - Commits and returns `next_turn`.
  - `get_session_turns(db: AsyncSession, current_user: User, session_id: str) -> List[InterviewQuestionTurn]`:
    - Returns all turns for the session ordered by `turn_index`.

### Task 2: REST API Turn Endpoints
- Update `backend/app/api/v1/endpoints/interviews.py`:
  - `POST /sessions/{session_id}/start` -> `InterviewQuestionTurnResponse` (Status 200)
  - `GET /sessions/{session_id}/current-turn` -> `InterviewQuestionTurnResponse` (Status 200)
  - `POST /sessions/{session_id}/turns/{turn_id}/answer` -> `TurnAnswerSubmissionResponse` (Status 200)
  - `GET /sessions/{session_id}/turns` -> `List[InterviewQuestionTurnResponse]` (Status 200)

### Task 3: Integration Tests for Turn Lifecycle & Pacing
- Create `backend/tests/test_interview_turns.py`:
  - Test `/start` generates turn 0 and is idempotent.
  - Test `/current-turn` returns active turn.
  - Test answer submission updates turn duration and answer.
  - Test dynamic follow-up turn creation with `parent_turn_id` link.
  - Test full 6-core question interview completion transitions session to `evaluating`.
  - Test quick 3-core question interview completion.
  - Test hard turn cap enforcement (cannot exceed `max_total_turns`).
  - Test `/turns` returns full ordered transcript history.
