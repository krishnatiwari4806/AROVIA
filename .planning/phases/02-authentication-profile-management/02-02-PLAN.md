<threat_model>
### Security Threat Model (ASVS L1)
- **T-02-04 (Brute-Force & Credential Stuffing):** Risk of automated password guessing against candidate accounts. Mitigation: SlowAPI IP throttling (10 req/min on `/login`), progressive 2-second sleep delay when `failed_login_attempts >= 3`, and 15-minute temporary lockout when `failed_login_attempts >= 5`.
- **T-02-05 (Token Interception & XSS Exfiltration):** Risk of JavaScript stealing long-lived session credentials from `localStorage`. Mitigation: Refresh tokens are delivered exclusively in `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/api/v1/auth` cookies; access tokens are held in client memory only.
- **T-02-06 (Refresh Token Replay):** Risk of attacker reusing an intercepted or stale refresh token. Mitigation: Strict single-use rotation—revoking the presented token and rejecting any request attempting to use an already-revoked token.
</threat_model>

<task type="auto">
  <name>Task 2: Implement AuthService and Auth API Endpoints</name>
  <files>backend/app/services/auth_service.py, backend/app/api/v1/endpoints/auth.py, backend/app/main.py</files>
  <read_first>backend/app/schemas/auth.py, backend/app/models/user.py, backend/app/core/security.py, docs/TRD.md</read_first>
  <action>
    1. Create `backend/app/services/auth_service.py`:
       - `register_user(db, register_data) -> (User, str, str)`: Checks email uniqueness (raises `ConflictError` if exists), hashes password with bcrypt, creates `User`, generates access token and 32-byte raw refresh token, inserts SHA-256 hash in `refresh_tokens`, returns `(user, access_token, raw_refresh_token)`.
       - `authenticate_user(db, email, password) -> (User, str, str)`: Looks up user. If user locked out (`lockout_until > NOW()`), raises `UnauthorizedError("Invalid email or password")`. If bad password or user not found, increments `failed_login_attempts`, sets `lockout_until = NOW() + 15m` if attempts >= 5, applies 2s progressive delay if attempts >= 3, and raises `UnauthorizedError("Invalid email or password")`. If valid, resets `failed_login_attempts = 0` and `lockout_until = None`, issues access token + new refresh token, returns `(user, access_token, raw_refresh_token)`.
       - `rotate_refresh_token(db, raw_refresh_token) -> (User, str, str)`: Hashes presented token, finds matching `RefreshToken`. If missing, expired, or `revoked == True`, raises `UnauthorizedError("Invalid or expired refresh token")`. Marks old token `revoked = True`, generates new raw refresh token, stores new SHA-256 hash, issues fresh access token, returns `(user, new_access_token, new_raw_refresh_token)`.
       - `logout_user(db, raw_refresh_token)`: Hashes token, marks record `revoked = True` if found.
    2. Create `backend/app/api/v1/endpoints/auth.py`:
       - Helper `set_refresh_cookie(response: Response, raw_token: str)`: Sets cookie `refresh_token` with `httponly=True`, `secure=(settings.ENVIRONMENT != "development" and settings.ENVIRONMENT != "testing")`, `samesite="lax"`, `path="/api/v1/auth"`, `max_age=604800`.
       - Helper `clear_refresh_cookie(response: Response)`: Deletes cookie with matching path.
       - `POST /register`: Accepts `UserRegisterRequest`, returns `TokenResponse` (201 Created), sets refresh cookie.
       - `POST /login`: Accepts `UserLoginRequest`, returns `TokenResponse` (200 OK), sets refresh cookie.
       - `POST /refresh`: Reads cookie `refresh_token`, returns `TokenResponse` (200 OK), sets new rotated cookie.
       - `POST /logout`: Reads cookie `refresh_token`, revokes token, clears cookie, returns `MessageResponse`.
    3. Update `backend/app/main.py` to register SlowAPI rate limiter state and middleware.
  </action>
